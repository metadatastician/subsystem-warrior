= subsystem-warrior — proposed directory layout
:toc:

Status: *proposal*, for approval with the plan PR. Nothing below exists yet
except where marked _(exists)_.

== Constraints this layout respects

The template's canon fixes most of the shape. The layout below adds no new
root entry and no new `src/` unit. Every path is a slot the canon already
names.

* *Root allowlist is bidirectional* (`.machine_readable/root-allow.txt`,
  `scripts/check-root-shape.sh`): no new root entries. So there is no root
  `fixtures/`, no root `receipts/`, and no second `Justfile`.
* *`src/` units* (deed `ply`): core logic in `core/`, verified seams in
  `interface/`, safety constraints in `contracts/`, failure dictionaries in
  `errors/`. *ABI MUST be Idris2*, *FFI MUST be Zig*; the "Truth" lives in
  `interface/Abi/`, the "Implementation" in `interface/ffi/`.
* *Justfile is thin* and delegates phases to `build/just/*.just` (it already
  imports `validate`, `proofs`, `container`, …).
* *Evidence is reproducible and documented* under `verification/`
  (deed `ply`, verification pillar).
* *Data formats* (estate route): machine-written records are I-JSON/JCS
  (`.json`, checked by `scripts/check-ijson-jcs.sh`); estate config is KYAML;
  Guix files stay Scheme.
* *Pre-mint compile limit:* `src/interface/ffi/src/main.zig` carries template
  tokens until `just repo-init`, so the existing `zig build test` step only
  compiles in a minted repo (`src/interface/ffi/build.zig`, header comment).

== Notes on the less obvious choices

. *Verified vs. shell is a directory boundary, not a convention.* Atoma cannot
  yet check allocators, recursion, callbacks, threads, `@cImport` or ambient
  I/O (brief §Atoma). Putting everything Atoma checks under `verified/` lets a
  gate say "every file here is in the subset" and lets `zig-vhdx` /
  `zig-ext4-ro` be lifted out later as whole directories. Parsers are described
  as "Atoma-checked, Warrant", never "proved".
. *The fixture generator does not reuse the reader's code.* `tests/fixtures/wsl/gen`
  writes VHDX/ext4 structures, and `src/interface/ffi/src/verified` reads them.
  If they shared a CRC or struct module, a shared misreading of [MS-VHDX] would
  pass both sides silently. The duplication is the price of an independent
  check. qemu-img and e2fsprogs remain the third-party oracles.
. *Fault ids live in `src/errors/faults.json`.* Fixture manifests, reader
  output, E2's baseline table and (in M1) W6 reports all name faults by the
  same id, so a single join answers "which fixture, which detector, which
  cost".
. *Zig parsers sit in `interface/ffi/`, not `core/`.* The canon reserves
  `core/` for core logic and says FFI MUST be Zig. Brief §Languages puts
  binary parsing in Zig and the state machine in Idris2. So the Idris2 model
  goes to `core/`, and the Zig parsers are the implementation side of the
  seam whose types will live in `Abi/`.
. *A separate `m0` build step* lets E3/E4 compile and test before mint, without
  touching the template's `main.zig`. If the owner mints before E3 starts, the
  step can fold into `zig build test`.
. *Receipts live under `verification/tests/m0/`, not `docs/reports/`.*
  `docs/reports/` canon covers audit, compliance, maintenance, performance,
  quality and security reports. Experiment evidence is what the verification
  pillar is for.

== Not decided by this layout

* Where the rescue distro image is built (likely `build/container/`, using the
  existing stapeln + Containerfile scaffolding) — waits on the owner's base
  choice (Alpine vs. Wolfi).
* The Windows executable's build entry point — waits on E6 and on the
  cross-compilation question.
