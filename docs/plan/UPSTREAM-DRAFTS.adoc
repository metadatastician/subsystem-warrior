== U1 — `rsr-template-repo`: address deed clauses by `:id`

*Where:* `hyperpolymath/rsr-template-repo`, `scripts/deed-field.sh` and
`scripts/deed-clause.sh`. Every minted repo inherits the fix.

*Problem:* a PATH segment selects the *first* child clause of that name.
Sibling `(directory …)` clauses in `(ply …)` after the first therefore cannot
be read or written by the one writer. Example: the `docs-pillar` clause's
`canonical-locations`. subsystem-warrior needs to register `docs/plan/`
there (plan ruling P5) and cannot without a hand edit, which the deed forbids.

*Proposal:* two changes, both needed:

. accept a selector `name[id]` in PATH that matches `:id "<id>"`, e.g.
  `ply/directory[docs-pillar]/canonical-locations`, keeping the existing
  first-match behaviour when no selector is given;
. add an *insert* operation. Today `set` only replaces an existing
  top-level scalar and exits 1 when the key is absent, and the
  `docs-pillar` `canonical-locations` clause has no `:plan` key yet. Add,
  for example, `deed-clause.sh add DEED PATH KEY VALUE`, which appends
  `:KEY VALUE` to the clause, refuses (exit 1) if the key already exists so
  it can never silently overwrite, and re-reads the result with
  `deed-field.sh` like every other write.

*Done when:* `deed-clause.sh add DEED ply/directory[docs-pillar]/canonical-locations plan '"plan/"'`
works and the result re-reads with `deed-field.sh`. `tests/workflows/deed_clause_test.sh`
must also cover: a selector hit, a selector miss (exit 1), the old
behaviour, an insert of a new key, and a refused insert of an existing key.

== U3 — `rsr-template-repo`: keep review bots out of identity files

*Where:* `hyperpolymath/rsr-template-repo`, `.coderabbit.yaml` (every minted
repo inherits it).

*Problem:* CodeRabbit's "fix CI failures" finishing touch pushed a commit that
renamed the deed, bumped the canon pin, and hand-edited the generated
`CLAUDE.md`, `ROADMAP.adoc` and `root-allow.txt` to turn `Canon lockstep`
green on an unminted repo. That is a partial mint by a bot (doctrine 5:
satisfy the gate, do not bypass it; doctrine 11: stop-first).

*Proposal:* configure CodeRabbit so that its autofix, CI-fix and unit-test
agents never edit `*_chora.deed`, `CLAUDE.md`, `.machine_readable/**`,
`docs/status/ROADMAP.adoc` or `.github/rulesets/**`, or disable the CI-fix
finishing touch estate-wide. The exact keys must be checked against
CodeRabbit's schema v2. This session could not reach `coderabbit.ai` to read
it, so no key names are given here.

*Done when:* a CI-fix run on a test PR with a red `Canon lockstep` makes no
change to those paths.

== U4 — estate: CodeQL default setup vs. the template's `codeql.yml`

*Where:* every repo minted from `rsr-template-repo` (settings), plus a note in
the template's mint checklist.

*Problem:* with CodeQL *default setup* enabled in repository settings, the
template's advanced `.github/workflows/codeql.yml` fails on upload: "CodeQL
analyses from advanced configurations cannot be processed when the default
setup is enabled". The owner ruled (2026-10-27) to disable default setup and
keep the template workflow.

*Done when:* `just repo-init` (or its checklist) tells the owner to turn
default setup off, and an estate sweep confirms no minted repo has both.
